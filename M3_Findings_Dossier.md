## 1. Problem & Motivation

M3 addresses federated anomaly detection for ambulance IoT vital-sign streams under three
simultaneously-relevant real-world constraints: **privacy** (patient data cannot leave the ambulance,
motivating differential privacy), **federation** (each ambulance is a separate client with a small
local data pool), and **connectivity** (ambulances operate in variable-quality cellular environments,
motivating robustness to packet loss, latency, bandwidth limits, and dropout). The roadmap's own
publication-strategy table names "(ε,δ)-DP federated anomaly detection under network degradation" as
M3's specific hook — i.e., the *joint* characterization across all three axes, not any one alone, is
the intended contribution. Most prior federated/DP anomaly-detection work characterizes at most one or
two of these axes in isolation; M3's contribution is measuring all three together, on the same
architecture, with the same evaluation protocol, so the axes are genuinely comparable to each other.

## 3. Method

### 3.1 Data
MIMIC-IV Waveform Database, 81 of the roadmap's target 198 patients (the portion downloaded and
complete as of this session — **a real, stated scope limitation, not the full target cohort**).
Three channels: ECG lead II, PPG/SpO₂, respiration — chosen as the broadest common subset realistically
matching a portable ambulance monitor (surveyed across the 81 patients: Resp/II/Pleth present in
80/76/68 of 83 surveyed records). 10-second windows (625 timesteps at the dataset's fixed 62.4725 Hz
sampling rate) — a 30-second window was tried first and caused near-flat training loss over 20 epochs
(too long a sequence for a single-layer LSTM to learn to reconstruct in that budget); 10s cuts sequence
length ~3× while still spanning multiple cardiac/respiratory cycles. Per-patient, per-channel z-score
normalization (not per-window), so window-level amplitude anomalies stay visible relative to that
patient's own normal range.

### 3.2 Architecture: two-detector ensemble
- **LSTM-Autoencoder.** Per-timestep-bottleneck decoder: encoder → per-timestep `Linear` bottleneck
  (`latent_size=16 < hidden_size=32`, enforcing genuine per-timestep compression) → `Linear` expand →
  decoder LSTM → output layer. This replaced an earlier repeat-vector design (encoder's final hidden
  state repeated at every decoder timestep) that collapsed to near-constant output (reconstruction std
  0.02–0.29 vs. input std 1.0–1.15) — the decoder had no time-varying input to work from, and MSE
  optimization found predicting near the mean at every step an easier minimum than unfolding real
  dynamics from a constant. The fix (real per-timestep signal into the decoder) restored healthy
  reconstruction (loss 0.25→0.009 over training; recon std 0.86–1.04 vs. input 1.0–1.15).
- **Variance detector.** Operates directly on windowed per-channel variance (rolling 1.0s window),
  calibrated at the 5th percentile of validation scores, per channel. Added after discovering the
  LSTM-AE is *structurally* blind to dropout/flatline anomalies: a well-trained reconstruction model
  finds sustained near-constant segments *easy*, not hard, to reconstruct (verified via per-timestep
  error-ratio analysis: spike anomalies produce ~1413× the error inside vs. outside the injected
  segment; dropout only ~1.27×; flatline ~0.56× — i.e. *lower* error inside the flatline segment).
  Does not depend on the trained model at all — its calibration depends only on the fixed validation
  split, confirmed identical across every regime tested (§5.5).
- **Fusion.** Logical OR of the two detectors' binary decisions. No learned combination weight — this
  is a deliberate simplicity choice, not yet ablated against a learned fusion (a real, stated gap for
  future work, not attempted here per the current architecture freeze, §7.6).

### 3.3 Privacy mechanism: DP-SGD via Opacus
Local DP-SGD inside NVFlare FedAvg. Gate-approved design (`M3_DP_Threat_Model_Gate.md`):
- **Privacy unit: patient (record-level), not window-level.** One window per patient per round —
  asserted and logged every round, every client, every K, verified via `SwappableWindowDataset` +
  `sample_one_window_per_patient()`; `all_rounds_ok=True` in every saved round-verification log across
  every regime and seed tested.
- **Pre-registered clipping norm C**, derived from a single unclipped, unnoised dry backward pass on
  round-0 data (before any DP training starts), never tuned post-hoc.
- **Cross-round composition**: the same `PrivacyEngine`/accountant object persists across all rounds
  (not reset per round) — ε accumulates monotonically, real per-round values logged.
- **Target ε = 1.0, δ = 1e-4**, fixed by the roadmap.
- `nn.LSTM` is incompatible with Opacus's per-sample-gradient hooks; `opacus.layers.DPLSTM` is used as
  a verified drop-in replacement (confirmed ~1e-7 numerical difference from an equivalent `nn.LSTM`
  with the same weights).
- **Batch size**: `max(1, min(16, n_patients // 2))`, capped at 16. This targets the supervisor's
  "B≈8–16" guidance while keeping the sampling rate q < 1 (privacy amplification preserved) and the
  one-window-per-patient invariant automatic (each round's dataset already has ≤1 window per patient by
  construction).

### 3.4 Federated aggregation: NVIDIA FLARE
`FedAvgRecipe` + `SimEnv` (in-process simulator), no custom server code — FedAvg is NVFlare's own
`ScatterAndGather`/`FedAvg` controller, used as-is per the roadmap's "no from-scratch reimplementation
of a mandated baseline" rule. `ParamsType.DIFF` + `DataKind.WEIGHT_DIFF` for the DP path (weight-diff
reporting, matching NVFlare's own `hello-dp` example pattern); `ParamsType.FULL` for the non-DP path.
Patients partitioned into K disjoint simulated-ambulance clients (`assign_ambulance_clients`,
deterministic given a seed) — K ∈ {10, 5, 3, 1} for the DP sweep, K=10 fixed for the non-DP/connectivity
baseline (matching the roadmap's 10-ambulance fleet framing).

### 3.5 Connectivity-robustness simulation
New this session (`network_sim.py`), SimPy-based, at the roadmap's fixed Good/Moderate/Poor parameter
values (not ranges): packet loss 1/5/10%, latency 50/200/500ms, bandwidth 10/2/0.5 Mbps, dropout
5/20/40%. Three independent gates per (client, round): dropout (Bernoulli), packet loss (Bernoulli,
applied directly as message-failure probability — *not* compounded per-packet, which would
inflate "Good" to a much higher effective loss rate), and a bandwidth-contention deadline gate
(`latency + payload / effective_bandwidth <= 3.0s`, `effective_bandwidth = profile.bandwidth /
n_active_clients_this_round`, modeling fair-share contention via a real `simpy.Environment` per round).
Payload size (62,777 bytes) measured directly from the real on-disk checkpoint, not estimated. A
`min_survivors=1` guard forces the fastest client through when every client would otherwise fail
delivery — a simulation-infrastructure necessity (NVFlare's `ParamsType.FULL` path does a wholesale
model replace; a round with zero deliveries would permanently null the global model and crash the next
round's `strict=True load_state_dict`), not a network-modeling assumption; it fired in 10 of 100
client-round slots under Poor at seed 42, disclosed explicitly rather than hidden. Integrated into the
non-DP federated pipeline only — deliberately not the DP pipeline, since the DP client's
`PrivacyEngine`/optimizer/accountant are constructed once at round 0 and persist across rounds, so
silently skipping a round there would reopen already-gate-approved DP-accounting questions.

### 3.6 Evaluation protocol
Patient-level 70/15/15 train/val/test split (no patient's windows appear in more than one split),
identical across every regime at a given seed. Adaptive threshold: 95th percentile of the held-out
validation set's reconstruction-error distribution (not the training set, to avoid an optimistic
threshold; preferred over mean+k·std since reconstruction error is right-skewed and bounded below by
zero). Synthetic anomaly injection (spike/dropout/flatline, 50% anomaly rate) on held-out test-patient
windows — approved "Option A" evaluation methodology, since real labeled clinical/sensor anomaly events
are not available in this dataset. **This is a real, stated limitation** (§7.3): reported F1/precision/
recall describe detection performance against this injection methodology, not validated real-world
incident rates.

## 4. Results — Axis 1: Privacy

Full table: `paper_assets/tables/privacy_k_sweep.tex`.

| K (clients) | Patients/client | Noise multiplier σ | Achieved ε | Protocol-compliant |
|---|---|---|---|---|
| 10 | 7–9 | 8.52–10.31 | 0.96–1.00 | Yes (10/10) |
| 5 | 14–17 | 3.63–3.98 | 0.76–0.79 | Yes (5/5) |
| 3 | 26–27 | 2.93–2.97 | 0.77–0.80 | Yes (3/3) |
| 1 | 79 | 6.60 | 0.99 | Yes (1/1) |

**Non-obvious real finding**: σ is *not* monotonic in K. It drops from K=10→K=3 as expected (larger
per-client pools improve subsampling amplification), but rises again at K=1 despite K=1 having by far
the most patients per client. Cause: batch size is capped at 16; once n exceeds 32 the batch stops
growing but the number of steps per epoch keeps growing, and the accountant must raise σ to hold the
same target ε over more composed steps — a real accountant-mechanics effect (§3.3), worth stating
explicitly rather than assuming "more data always means less noise." Figure: `fig2_sigma_vs_k.pdf`.

### 5.1 The key statistical result
Across all 9 regimes (utility + connectivity), the standard deviation **between** the 9 regime means is
0.005 combined F1; the average standard deviation **within** a single regime (across its own 5 seeds)
is 0.027 — roughly 5× larger. Two runs of the *same* regime at different seeds typically disagree with
each other more than the means of two *different* regimes disagree with each other. This is the
descriptive form of the finding; §5.3 gives the formal statistical test.

### 5.2 The DP-SGD collapse: real, unresolved, and directly measured
Full table: `paper_assets/tables/collapse_evidence.tex`; raw data: `m3_collapse_diagnostic.json`.
Reconstruction std vs. input std, measured directly on the actual checkpoints behind every F1 number
above (pure diagnostic load, no new training):

| Regime | recon_std / input_std | Status |
|---|---|---|
| Non-DP Federated K=10 (healthy reference) | 0.95–1.00 | Not collapsed |
| DP Federated K=10 | 0.0025–0.0027 | **Collapsed** |
| DP Federated K=5 | 0.0022–0.0036 | **Collapsed** |
| DP Federated K=3 | 0.0038–0.0079 | **Collapsed** |
| DP Federated K=1 | 0.0031–0.0100 | **Collapsed** |

**This is a real, unresolved finding — write it precisely, not optimistically.** The LSTM-AE genuinely
collapses to near-constant output under DP-SGD at every tested K, today, in the exact checkpoints
behind every number in this dossier. No evidenced code fix resolves it: `module 3` is its own git
repository, but `dp_federated_client.py` has exactly one commit, already containing the current
batch-size-cap formula — there is no iterative before/after diff to cite, and none was found by direct
investigation. The batch-size-cap formula changed the noise multiplier σ (privacy accounting, §4) — it
did not resolve the collapse. **Required precise claim wording** (specified by the supervisor's 20 Aug
approval memo, verbatim): *"DP degrades reconstruction fidelity but does not produce a statistically
distinguishable degradation in downstream ensemble anomaly-detection F1 under the tested conditions."*
Not "DP has no effect." Figure: `fig4_collapse_evidence.pdf`.

**Why downstream F1 survives a genuinely collapsed model**: the variance detector alone reaches
F1≈0.483 regardless of the LSTM-AE's state (§5.5) — a floor that exists independent of collapse. On top
of that floor, even a collapsed, near-constant-output LSTM-AE's reconstruction error still weakly ranks
large-magnitude (spike) deviations above baseline: a spike is a big enough perturbation that
reconstructing it "wrong" (the model outputs roughly the same constant regardless of input) produces
measurably higher error than reconstructing a normal window equally "wrong" in the same collapsed way.
That signal is weak (LSTM-AE-only F1 stays well below the non-collapsed centralized ceiling) but real,
adding ≈+0.16 combined F1 on average, never near zero.

### 5.3 Formal equivalence test (TOST, Δ=0.05 F1)
Full table: `paper_assets/tables/equivalence_test.tex`. Required by the supervisor's memo: a justified,
pre-specified margin (Δ=0.05 F1, the supervisor's own value — not chosen from the data) with a formally
pre-specified statistical procedure. Method: two one-sided tests (TOST), each of the other 8 regimes
vs. **Centralized as reference**, Welch (unequal-variance) two-sample formulation on the 5-seed
combined-F1 samples; equivalence established when the 90% CI of the mean difference lies entirely
inside [−0.05, +0.05]. Computed with `scipy.stats` (`analyze_multiseed.py`), real p-values.

| Regime (vs. Centralized) | Mean diff. | 90% CI | TOST p | Verdict |
|---|---|---|---|---|
| Non-DP Federated K=10 | +0.0076 | [−0.018, +0.033] | 0.0071 | Equivalent |
| DP Federated K=10 | +0.0043 | [−0.027, +0.035] | 0.0127 | Equivalent |
| DP Federated K=5 | +0.0043 | [−0.026, +0.035] | 0.0124 | Equivalent |
| DP Federated K=3 | +0.0053 | [−0.026, +0.036] | 0.0144 | Equivalent |
| DP Federated K=1 | +0.0066 | [−0.023, +0.036] | 0.0132 | Equivalent |
| Connectivity Good | +0.0061 | [−0.027, +0.039] | 0.0189 | Equivalent |
| Connectivity Moderate | +0.0071 | [−0.024, +0.038] | 0.0167 | Equivalent |
| Connectivity Poor | +0.0189 | [−0.013, +0.051] | 0.0544 | **Not established** |

7 of 8 regimes formally equivalent at α=0.05, including the *entire* DP K-sweep. Connectivity Poor's
90% CI extends 0.001 past the +0.05 margin (p=0.054, essentially borderline) — reported honestly as
"not established," not rounded into significance. Consistent with §5.1: Poor also had the largest
single-regime seed-to-seed std (0.030) of any regime, so a 5-seed test has the least power there.
**Caveat to keep in any paper draft**: n=5 per group is a small sample for a t-test-based procedure —
the point estimates and direction are informative, but a peer-reviewed venue may reasonably ask for
more seeds, particularly to resolve the Poor-connectivity borderline case (§7.1).

### 5.4 Corrections and retractions (a research-integrity asset, not just a caveat list)
Documenting these carefully is itself part of the contribution — it demonstrates the verification
discipline behind every other number in this dossier:
1. **Retracted**: an earlier diagnostic claiming a large dataset (n=901) would recover DP utility was
   invalidated — it silently used `max_windows_per_patient=80` on too few distinct patients, violating
   the one-window-per-patient gate constraint. Never cited as evidence about the approved protocol.
2. **Corrected, then corrected again**: "DP-federated collapses at every tested K" was first
   (inaccurately) retracted as describing "an intermediate/unsaved state." Direct investigation (§5.2)
   showed the *original* collapse claim was right and remains true today; what was wrong was implying a
   fix resolved it. The precise, narrower, now-evidenced claim: downstream F1 does not collapse, despite
   the model itself remaining collapsed.

### 5.5 Per-anomaly-type, per-detector mechanism
Full table: `paper_assets/tables/anomaly_breakdown.tex`; figure: `fig3_anomaly_type_mechanism.pdf`
(one representative regime; the pattern below is consistent in direction across all 9 regimes — see
the full table for every regime). 5-seed mean ± std recall:

| Detector | Spike | Dropout | Flatline |
|---|---|---|---|
| LSTM-AE-only | 0.63–0.76 | 0.03–0.05 | 0.05 |
| Variance-only | 0.18 | 0.61 | 0.38 |
| Combined | 0.72–0.81 | 0.62–0.63 | 0.41 |

Variance-only recall is identical *within* a seed across every regime (confirmed at each of the 5
seeds independently) — it depends only on that seed's validation split, never on the model; its
cross-seed std (visible in the full table) is purely split-to-split variation. This is the mechanistic
explanation for §5.1/§5.2 in one table: the LSTM-AE-only detector is strong on spike and essentially
blind to dropout/flatline (the structural blindness that motivated adding the variance detector in the
first place, §3.2); the variance detector is the mirror image. The combined detector inherits the
stronger of the two on every anomaly type — dropout and flatline detection literally do not depend on
the LSTM-AE, which is why the ensemble's overall F1 stays stable regardless of what DP-SGD does to it.

| Profile | Packet loss | Latency | Bandwidth | Dropout |

| Good | 1% | 50ms | 10 Mbps | 5% |
| Moderate | 5% | 200ms | 2 Mbps | 20% |
| Poor | 10% | 500ms | 0.5 Mbps | 40% |

| Profile | Participation (a priori / observed) | LSTM-AE-only F1 | Variance-only F1 | Combined F1 |
|---|---|---|---|---|
| None (baseline) | 100% / 100% | 0.398 ± 0.058 | 0.483 ± 0.067 | 0.648 ± 0.019 |
| Good | 91–97% / match, all 5 seeds | 0.397 ± 0.051 | 0.483 ± 0.067 | 0.647 ± 0.031 |

| Poor | 10% / match, all 5 seeds | 0.424 ± 0.032 | 0.483 ± 0.067 | 0.660 ± 0.030 |

**Free correctness check, passed at every seed**: the a-priori participation rate (from the
pre-registered SimPy schedule, before training) matches the observed rate (from each client's own
round log, written during training) exactly in all three profiles, at all 5 seeds — confirming the
schedule → client → FLARE aggregation pipeline behaves exactly as designed.

**Consistent with the privacy-axis finding**: Poor's mean is nominally highest — the one regime (of 8)
the formal equivalence test (§5.3) could not establish as equivalent to centralized (p=0.054). Plausible
mechanism: under Poor, FedAvg is dominated by whichever one or two clients survive most often
(participation collapses toward a small effective K), the same "small effective K doesn't hurt this
pipeline" pattern on the privacy axis.

## 7. Limitations (carry verbatim into any paper draft)

1. **Statistical power at n=5 seeds.** Enough to run the TOST test and get a clear result for 7 of 8
   regimes, but still small for a t-test-based procedure — a peer-reviewed venue may reasonably ask for
   more seeds, particularly to resolve the Poor-connectivity borderline case. Infrastructure exists
   (`--seed` on every job/eval script) to extend cheaply.
2. **Dataset scale.** 81 of the roadmap's target 198 patients. Per-client pools at high K are
   correspondingly small (7–9 patients at K=10). External validity to the full cohort not yet
   established — re-running once the full download completes is recommended, non-blocking.
3. **Synthetic anomaly injection.** Not real labeled clinical/sensor incidents (§3.6). Reported metrics
   describe performance against the injection methodology, not validated real-world incident rates.
4. **Connectivity ablation scope.** Non-DP pipeline only (§3.5) — a deliberate, documented choice, not
   an oversight. Privacy and connectivity are reported as two separate axes, not their joint interaction.
5. **Operational layer not integrated.** Paho MQTT (mandatory baseline repo for the roadmap's real-time
   alerting layer) is vendored but not wired into any pipeline — deployment-track scope, deferred.
6. **DP-SGD model-level collapse is real and unresolved** (§5.2) — must never be described as fixed.
7. **No related-work literature review yet** (§2) — a real gap, to close with a genuine search before
   writing, not filled with remembered/invented citations.

## 8. Reproducibility

Seeds 42 (fixed-seed figures, e.g. the privacy table) and 42/123/7/456/789 (all 5-seed mean±std
tables and the equivalence test). Every job/eval script accepts `--seed` (default 42); outputs get a
`_seed{N}`/`-seed{N}` suffix so re-runs never overwrite the seed-42 canonical results.

```bash
python src/train_centralized.py [--seed N]
python src/federated_job.py --n_clients 10 --num_rounds 10 --epochs 4 [--seed N]
python src/federated_job.py --network_profile {good,moderate,poor} --n_clients 10 --num_rounds 10 --epochs 4 [--seed N]
python src/dp_federated_job.py --k_clients {10,5,3,1} --n_clients {10,5,3,1} [--seed N]
python src/evaluate_non_dp_federated.py [--network_profile {good,moderate,poor}] [--seed N]
python src/evaluate_dp_federated.py --k_clients {10,5,3,1} [--seed N]
python src/analyze_multiseed.py          # aggregates all seeds -> mean+/-std, anomaly breakdown, TOST
python src/measure_collapse.py           # recon_std/input_std diagnostic
python src/generate_latex_tables.py      # -> paper_assets/tables/*.tex
python src/generate_figures.py           # -> paper_assets/figures/*.pdf
```

**Compute**: `train_centralized.py` uses GPU (RTX 3050) when available — measured 29.0s vs. 198.5s on
CPU for the identical protocol, a real ~6.8× speedup. The federated/DP-federated pipelines deliberately
stay on CPU, enforced with `CUDA_VISIBLE_DEVICES=-1` set before any `torch` import: NVFlare's
in-process simulator shares one CUDA context across concurrently-running client threads, and
`device="cpu"` call sites alone were not sufficient to prevent reproducible CUDA out-of-memory crashes
at K=10 (some library code, most likely Opacus/DPLSTM setup, appears to touch CUDA whenever it is
merely available, not only when actually used).
